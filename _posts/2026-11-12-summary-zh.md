## 广告实操教程

<a id="item-adtech-practical-1"></a>
### [Neil Patel 落地页表单优化指南：七大策略提升线索转化](https://neilpatel.com/blog/the-definitive-guide-to-lead-generation-form-optimization/) ⭐️ 8.0/10

Neil Patel 发布了一份落地页 lead generation form 优化指南，主张通过 seven 项可测试的页面与表单策略提升转化率。他引用自己 672% 的提升、表单字段从 4 个减到 3 个后转化接近提升一半等数据，强调最终效果必须通过 split testing 验证。

rss · Neil Patel · 11月11日 17:00

**「机制」** 该指南把转化机制拆成 placement、CTA、信任与 friction 四层。它建议将表单和 CTA 放在 above-the-fold 以获得最大曝光，但同时承认复杂 offer 可能更适合 below-the-fold，并引用 Nielsen 对 above/below 内容处理差异 84% 的研究；这说明曝光并非充分条件，仍取决于 offer 复杂度与用户动机。其次，它强调强 CTA 文案、与 landing page copy 和 offer 标题的 message agreement，以降低理解成本。第三，围绕表单减少 friction：保留 white space、减少字段、把部分字段设为 optional、采用 two-step process，并用 privacy policy 建立信任。作者还用 HubSpot/Dan Zarrella 对 40,000 个 contact forms 的研究说明，字段从 4 减到 3 会带来近 50% 的 conversion lift；但他也给出反例，如把 CTA button 放大反而导致 10.56% 转化下降，说明不存在通用最优按钮。

**「启示」** 对广告平台和算法工程师而言，这条内容的价值不在某个单一 hack，而在把 CRO 视为一个以实验驱动的信号优化问题：页面位置、字段数量、信息一致性和信任提示都会影响转化函数。真正可迁移的结论是，平台或落地页产品应把 form placement、field count 和 CTA copy 纳入可测试变量，而不是假定 above-the-fold 或更大按钮总是更优。

## 推荐系统

<a id="item-recsys-1"></a>
### [Meta Intelligent Delivery：用 ML 分配广告推理算力](https://engineering.fb.com/2026/11/11/ml-applications/intelligent-delivery-serve-better-ads/) ⭐️ 9.0/10

rss · ML Applications - Engineering at Meta · 11月11日 17:00

**「背景」** 广告排序模型正朝着 LLM 级规模扩张，但算力供给跟不上模型复杂度增长，且同样一单位算力对不同请求、模型和硬件的边际收益差异巨大。Meta 撰文介绍 Intelligent Delivery，目标是解决在异构硬件、有限容量和严格延迟预算下，如何把每单位算力分配到全局收益最高处的问题。

**「方法」** 核心思路是把算力分配重构为 ML 问题：先预测每个请求的边际效用，再用分层机制执行分配。请求理解层是 Resource Core Model——6B 稀疏参数+20M 密集参数的深度学习模型，在候选检索前运行一次并在全漏斗共享，通过学习嵌入和深度特征交互替代人工分群规则；再将其微调为一组专用模型，分别预测结果收益、算力消耗和延迟影响，构成共享的分配智能层。分配层是一个决策引擎层级：区域级实时调度流量使各区域边际效率趋同；硬件级对每个 workload-SKU 对测量效率并求解分配（检索受内存约束、排序受算力约束、推理受加速器吞吐约束）；主机级在尾延迟 SLO 下求解带约束优化，负载升高时优先削减高资源低收益的请求，控制范围从内核调度器到应用线程池。第三层是优化闭环：AI agent 在长上下文窗口中阅读机制源码、设计文档和十年实验日志，提出少量值得测试的改动，由工程师审核上线。该方法有效的原因是它同时解决了三个问题：用统一模型估计跨阶段决策空间上每请求的回报，用分层引擎让全局决策可执行，用 agentic 闭环跟上持续变化的优化目标。

**「效果」** 作者称 Intelligent Delivery 自 2017 年至 2026 年上半年在主要版位上累计贡献约 10%的增量广告排序收益（叠加在模型与系统进步之上）。Resource Core Model 在识别高影响力请求的离线基准上较此前生产模型提升约 20%。2026 年上半年，AI agent 贡献了约 20%的 Intelligent Delivery 优化项，在自动化程度最高的机制上承担约 80%的工程工作量，将优化周期从数月缩短到数周。

**「启示」** 对广告排序工程师，可借鉴的是&quot;预测边际效用+分层决策&quot;的框架：用一个共享的小模型在请求早期预估其对算力的回报，再按区域/硬件/主机分层执行带约束优化。该思路适用于算力受限、多阶段漏斗、异构硬件的大流量排序系统；但收益依赖全栈控制能力（流量调度、内核级资源控制）和长期基建投入，小团队可先做单机/单阶段的 per-request 算力分配。

**标签**: `#ad ranking`, `#compute allocation`, `#CTR prediction`, `#serving optimization`, `#production ML system`

## LLM 与 Agent

<a id="item-ai-agentic-1"></a>
### [Jev 与 System One 模型：AI 工程峰会实践报告](https://latent.space/p/jev-revolution/) ⭐️ 7.0/10

本文报道了 AI Engineer Code Summit 上关于 System One 模型的讨论，这类非生成式模型返回结构化选择、分数或概率，比推理型 LLM 更快更便宜。TypeSafe AI CEO Diogo Almeida 作为 Jev 的创造者发表主题演讲，Glean、UiPath 和 Workday 的工程师分享了实际应用案例。

rss · Latent Space · 11月12日 05:08

**「要点」** Jev 是 TypeSafe AI 在两个月前发布的产品，主打“可靠智能”，主张将模型调用直接嵌入应用代码而非依赖拼接字符串的提示工程。Almeida 用“95%时间是爱因斯坦，5%时间是憨豆先生”形容 LLM 的不可靠性，认为 System One 模型应像“第四个逻辑门”一样可靠，实现“自动化一切”。Glean 的 Chinmay Goyal 介绍他们将 Jev 与 LLM 及其他分类器并用，看重其“零样本灵活性”——决策空间变化时无需反复微调；Jev 驱动了大量流程，但用户无需感知底层模型差异。UiPath 工程师展示了用 Jev 对文档块做锦标赛式排序：小组赛出线再晋级，数千次调用全程不到一秒，结论是 Jev 是可组合的构建块，配合策略和模式能获得更高智能。Workday 首席工程师 Scott Roberts 演示了原型：用户仍在输入时界面就开始预填请假卡，实现从“预测你想说什么”到“预测你想做什么”的转变。

**「启示」** 读者可以了解到 System One 模型作为代码内嵌构建块的具体用法——零样本分类、毫秒级批量排序、实时行为预测——并参考 Glean 和 UiPath 的模式判断何时用 Jev 替代或补充 LLM。
